**決定的証拠**: v1.2.0 Windows が +78 × 3 = 234 DL と主張しているが、

234 > 145 は数学的に不可能 → **スパイクは確実に二重計上**。

#### 1.4 根本原因の結論

- **一次要因（データ）**: DailyData に 2/16・2/24・2/27 の 3 日分の行が存在し、
  同一（または近似）の累積値が記録されている。
  各日にスクリプトが実行されたが、ダウンロードが発生しなかったため累積値が変化しなかった。
- **二次要因（ロジック）**: `getTimelineData()` の `prevCount` が 2/16 → 2/24 間で
  正しく引き継がれず、2/24 の同一累積値が「新規増分 +78」として計上される。
  原因の正確なメカニズムは、DailyData への直接アクセスがないため特定できなかったが、
  バグの存在は PoPuP 合計の矛盾から証明された。

### Prompt 2: 修正実装と検証（実装フェーズ）

#### 2.1 Apps Script 修正: maxSeenCount 導入

`config/google_apps_script.js` の `getTimelineData()` 内の増分計算ループを修正:

**修正前:**
```javascript
let prevCount = baseline;
dateList.forEach(date => {
  if (appData[appName][date] && ...) {
    const increment = Math.max(0, currentCount - prevCount);
    prevCount = currentCount;  // ← これがリセットされると問題
  }
});
```

**修正後:**
```javascript
let prevCount = baseline;
let maxSeenCount = prevCount;  // ← 追加: 過去最大累積値を追跡
dateList.forEach(date => {
  if (appData[appName][date] && ...) {
    const effectivePrev = Math.max(prevCount, maxSeenCount);  // ← prevCountリセット対策
    const increment = Math.max(0, currentCount - effectivePrev);
    prevCount = currentCount;
    maxSeenCount = Math.max(maxSeenCount, currentCount);  // ← 最大値を更新
  }
});
```
