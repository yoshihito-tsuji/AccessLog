### 2. 198 > 192 の理由（アルゴリズム分析）

**根本原因**: Apps Script の日次増分算出ロジック（[google_apps_script.js:236-251](config/google_apps_script.js#L236-L251)）において、**累積値が減少した日に負の増分が0に丸められる**ため。

**アルゴリズム**:
```javascript
// google_apps_script.js:236-251
versionNames.forEach(versionName => {
  let prevCount = 0;  // ← 初期値0
  dateList.forEach(date => {
    if (appData[appName][date]?.[versionName] !== undefined) {
      const currentCount = appData[appName][date][versionName];
      const increment = Math.max(0, currentCount - prevCount);  // ← 負の値は0に
      dailyData.push(increment);
      prevCount = currentCount;
    }
  });
});
```

**実測データによる証明**:

| バージョン | 差が生じた日 | prev → curr | increment | 説明 |
|------------|-------------|-------------|-----------|------|
| PoPuP (Mac) v1.3.1 | 2026-01-04 | 14 → 11 | 0 | -3が0に丸められた |
| PoPuP (Windows) v1.3.1 | 2026-01-04 | 14 → 11 | 0 | -3が0に丸められた |

**差の合計**: 6（= 198 - 192）

**なぜ累積値が減少したか**:
- GitHub Releasesのアセットが削除または置換された可能性
- または、リリースの公開状態変更（draft/prerelease切り替え）

**結論**:
- `Math.max(0, ...)` により負の増分が切り捨てられるため、増分合計が最終累積値を上回ることがある
- これは仕様通りの動作（異常ではない）
- 過去のダウンロード数は「なかったことにならない」設計
